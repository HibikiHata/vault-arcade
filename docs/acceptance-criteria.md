# Acceptance criteria

Numbered acceptance criteria referenced by test names (`AC-nnn`) and code comments. Each is written as Given / When / Then. Screen ids (`S-01` menu, `S-02` playing, `S-03` paused, `S-04` result) name the view's screens. Where a later criterion changes an earlier one (for example AC-042 replaces the menu layout of AC-032), the later one applies.

- **AC-001** — Given the plugin is enabled, when the ribbon icon is clicked or the command runs, then a tab titled "Vault Arcade" opens in the main area showing the menu (S-01).
- **AC-002** — Given the arcade tab is already open, when the command runs again, then the existing tab is activated and no second tab is created.
- **AC-003** — Given Obsidian restores a workspace that contains the arcade tab, when Obsidian starts, then the tab shows the menu and no game is running until the player presses Play.
- **AC-004** — Given the arcade tab is moved to a sidebar or a popout window, when the player starts a game, then it plays there without errors (layout may be smaller; no feature is lost).
- **AC-005** — Given the snake moves right, when the head reaches the cell containing food, then length increases by 1, score increases by 1, and a new food cell appears on a free cell chosen by the injected random source.
- **AC-006** — Given the head is in the rightmost column moving right, when the next tick occurs, then the game state becomes "over".
- **AC-007** — Given the snake moves right and length ≥ 2, when "left" is received, then it is ignored; when "up" then "left" are received within the same tick, then the next tick moves up and the following tick moves left (no reversal).
- **AC-008** — Given any state, when 1,000 consecutive ticks are simulated with random valid inputs and a seeded random source, then no exception is thrown and the snake never occupies a cell twice while the state is "running".
- **AC-009** — Given the snake occupies 399 cells, when it eats the last food, then the state becomes "won" and the score is 397.
- **AC-010** — Given the game is running on desktop, when ArrowUp or W is pressed, then the direction changes to up before the next tick, and the pane does not scroll.
- **AC-011** — Given the game is running on a touch device, when the player swipes right by ≥ 24 px anywhere in the arcade view with the horizontal component larger than the vertical, then the direction changes to right; a shorter movement is ignored.
- **AC-012** — Given the arcade tab does not have focus, when arrow keys or Space are pressed elsewhere in Obsidian, then the game does not react and the editor keeps its normal behavior.
- **AC-027** — Given the paused screen, when Quit is pressed, then the start screen is shown and the stored high score is unchanged; given the game-over screen, when Back or Escape is pressed, then the start screen is shown.
- **AC-013** — Given a game is running, when the arcade tab loses focus or becomes hidden (another tab is activated, the app goes to the background), then the game pauses automatically and the paused screen is shown on return.
- **AC-014** — Given "fast" is selected, when the game runs, then the tick interval is the configured fast interval (a constant in the source) and the choice survives an Obsidian restart.
- **AC-015** — Given a game played at speed S ends with a score higher than the stored high score for S, when the game-over screen appears, then it shows "New high score" and `saveData` has completed with the new value for S; other speeds' values are unchanged.
- **AC-016** — Given `data.json` is missing, malformed, or lacks a speed's key, when the plugin loads, then that high score is 0 and no exception is thrown; a pre-release file holding the single key `highScoreSnake` is migrated into the normal-speed value.
- **AC-017** — Given the plugin holds high score 12 for a speed in memory, when `data.json` changes externally (through Sync) to 9 for that speed, then the effective value stays 12 and is written back; when it changes to 20, then the effective value becomes 20. Each speed's key is merged independently.
- **AC-018** — Given the pane is resized or the device rotates, when the next frame renders, then the board fits the smaller pane dimension with no scrollbars.
- **AC-019** — Given the theme switches between light and dark, when the next frame renders, then board, snake, food, and text colors change with the theme without reloading the plugin.
- **AC-020** — Given the built files are placed in a vault's `.obsidian/plugins/vault-arcade/` and synced to an iPhone, when the arcade tab is opened, then every shipped game is playable end to end with touch alone (play, steer, pause where applicable, game over, restart).
- **AC-021** — Given the arcade tab was opened and closed twice, when a game runs, then exactly one loop and one set of listeners exist (verified in DevTools by counting registered handlers and frame callbacks).
- **AC-022** — Given a full row exists, when a piece locks, then the row is removed, rows above shift down, and the score increases per the scoring table in `src/core/blocks/constants.ts`.
- **AC-035** — Given a piece stands against the left wall in an orientation whose clockwise rotation would overlap the wall, when rotate is input, then the piece rotates and shifts one column right; given no shift of 0, −1, +1, −2, or +2 columns fits, then the state object is returned unchanged.
- **AC-036** — Given the game is running, when drop is input, then the piece moves to the lowest free position, locks immediately, full rows clear, and the next piece spawns within the same input.
- **AC-037** — Given the piece can move down, when a downward turn (soft drop) is input, then it moves down one cell and does not lock; given it rests on the floor or on a block, then the state object is returned unchanged.
- **AC-038** — Given the piece rests on a surface, when the lock delay (a fixed number of ticks) elapses without a downward move, then the piece locks; given it moves down before that, then the delay starts over.
- **AC-039** — Given 9 lines have been cleared, when a tenth line clears, then the level becomes 2 and the fall interval shortens per the scoring table in `src/core/blocks/constants.ts`; the table is clamped at its last entry for higher levels.
- **AC-040** — Given the next piece's spawn cells overlap locked blocks, when the current piece locks, then the phase becomes `over` and the score is kept.
- **AC-041** — Given any seven consecutive pieces aligned to a bag boundary, when they are drawn, then every shape appears exactly once.
- **AC-042** — Given the arcade tab opens, when the menu (S-01) shows, then it lists Snake, 2048, and Blocks under one speed selector shared by Snake and Blocks, whose bests follow the selected speed; a Blocks result is stored under the key of the speed it was played at; in a pane shorter than the menu the menu scrolls.
- **AC-043** — Given Blocks is running with the board focused, when Space is pressed, then the piece hard-drops and the game does not pause; when P is pressed in any tick game, then pause toggles; when a key is held so that the browser auto-repeats it, then only left, right, and down repeat (rotate, drop, pause, start, and quit fire once); when a key is pressed with Cmd, Ctrl, or Alt, then the game ignores it and Obsidian handles it.
- **AC-044** — Given Blocks is running on a touch device, when the player taps the view, then the piece rotates; when the player swipes left or right, then it moves one column; when the player swipes down, then it hard-drops; when the player swipes up, then it rotates; when the player taps the HUD Pause button, then the game pauses (S-03).
- **AC-045** — Given Snake or 2048 is running, when rotate or drop is received, then the state object is returned unchanged; Snake's Space and tap still toggle pause as in 1.1.0 (the only differences for Snake and 2048 are additive: the HUD Pause button, the P key, score announcements per input, and the repeat / modifier key policy of AC-043).
- **AC-046** — Given a piece is falling with at least one free row beneath it, when the board is drawn, then a thin outline of the piece in the same color marks where it would land with the current column and rotation; given the piece rests on the floor or the stack, then no outline is drawn.
- **AC-047** — Given a lock clears one or more rows, when the board is drawn, then the cleared rows flash and fade for about 180 ms over the pre-clear board before the collapsed board appears, while play continues; given `prefers-reduced-motion: reduce`, then the collapsed board appears immediately (AC-026).
- **AC-048** — Given a piece is falling, when the board is drawn, then the next piece shown beside the well is the piece that spawns after the current one locks (the bag is refilled as soon as it empties, so a next piece always exists).
- **AC-049** — Given Blocks is running on a touch device, when the player drags a finger horizontally without lifting it, then the piece moves one column for every 24 px of travel while the horizontal travel exceeds the vertical; when the finger lifts after such a drag, then no tap or swipe action fires.
- **AC-023** — Given a row [2, 2, 4, 0], when the player moves left, then the row becomes [4, 4, 0, 0] and the score increases by 4.
- **AC-028** — Given a row [2, 2, 2, 2], when the player moves left, then the row becomes [4, 4, 0, 0] (each tile merges at most once) and the score increases by 8.
- **AC-029** — Given a board where a move changes nothing (for example moving left on a row [2, 4, 8, 16] with every row already packed left), when that move is input, then no tile spawns, the score is unchanged, and the state object is returned unchanged.
- **AC-030** — Given a move changes the board, when it completes, then exactly one new tile (2 or 4) occupies a previously empty cell chosen by the injected random source.
- **AC-031** — Given no empty cell and no two equal neighbours, when the state is evaluated, then the phase is `over`; given a 2048 tile appears for the first time, then the phase is `won` and Keep playing returns to `running` without resetting the board.
- **AC-032** — Given the arcade tab opens, when the menu (S-01) shows, then it lists Snake and 2048 with each game's best score and a Play button per entry; Play starts that game immediately; only the Snake entry carries the speed selector.
- **AC-033** — Given a row [2, 2, 2, 0], when the player moves left, then the row becomes [4, 2, 0, 0] and the score increases by 4 (merging starts from the wall the tiles move toward: slide, merge adjacent equal pairs from that wall outward, slide again).
- **AC-034** — Given the phase is `over` or `won`, when `start` is received (Enter), then a fresh game starts, the same as `restart`.
- **AC-024** — Given a phone pane whose effective board width (pane width minus board padding and borders) is 384 px, when the preset list is shown, then only presets with ≤ 12 columns are selectable (384 / 12 = 32 px per cell).
- **AC-050** — Given a fresh board, when the first cell is revealed, then it is not a mine, the mines are placed at that moment excluding the revealed cell and its eight neighbours when at least `mines` other cells remain (otherwise excluding only the revealed cell), and the injected random source is consumed exactly `mines` times.
- **AC-051** — Given a revealed cell has no adjacent mines, when it is revealed, then every neighbouring cell is revealed too, recursively, and each revealed cell shows its count of adjacent mines (1–8) or nothing for zero.
- **AC-052** — Given a hidden cell, when flag is input (long-press, right click, or F), then it toggles a flag; given a flagged cell, when reveal is input, then nothing changes (same state object); given a revealed cell, when flag is input, then nothing changes.
- **AC-053** — Given a hidden mine cell, when it is revealed, then the phase becomes `over`, every unflagged mine is shown, correctly flagged mines keep their flag, the revealed one is marked as exploded, flags on non-mine cells are marked wrong, and the score (safe cells revealed so far) is kept.
- **AC-054** — Given the last hidden safe cell, when it is revealed, then the phase becomes `won` regardless of flags.
- **AC-055** — Given the menu shows on a phone (Obsidian `Platform.isPhone`), when the Minesweeper presets are listed, then only presets whose board-width ÷ columns is ≥ 32 px appear (≥ 24 px on other devices); given the board has not been laid out yet (width 0), then every preset appears; given no preset qualifies, then the smallest appears; given the board width changes while the menu is shown, then the list updates.
- **AC-056** — Given a stored preset, when the menu shows, then it is selected; given the stored value is unknown, then Small is used; given the stored preset is unavailable on this device, then the largest available is shown without writing the fallback back; given the setting changes on another device through Sync, then this device adopts it (settings follow the disk; scores merge by maximum).
- **AC-057** — Given the board has keyboard focus, when ArrowLeft / ArrowRight / ArrowUp / ArrowDown or A / D / W / S is pressed, then the cursor moves one cell (clamped at the edges) and is visible; when Space is pressed, then the cursor cell is revealed; when F is pressed, then the cursor cell's flag toggles.
- **AC-058** — Given a touch device, when a cell is tapped (released within 500 ms after moving less than 10 px), then it is revealed at the touch release; when a cell is pressed for 500 ms, then a flag toggles and the release does not reveal; when the finger moves more than 10 px, then nothing happens.
- **AC-059** — Given a desktop pointer, when a cell is left-clicked, then it is revealed; when it is right-clicked, then a flag toggles and no browser context menu opens.
- **AC-060** — Given the menu shows, when the Minesweeper entry is displayed, then it carries the preset selector and shows the best for the selected preset; the best of a game is stored under the key of the preset it was played at (`highScoreMinesweeperSmall` / `Medium` / `Large`) and merges by maximum.
- **AC-061** — Given Snake, 2048, or Blocks is running, when a cell action is received, then the state object is returned unchanged; given Minesweeper is running, when pause, resume, toggle-pause, continue, rotate, or drop is received, then the state object is returned unchanged.
- **AC-025** — Given a generated puzzle, when the player fills every cell correctly, then the game reports completion and time; the puzzle has exactly one solution (verified by the generator's test).
- **AC-026** — Given `prefers-reduced-motion: reduce`, when a line clears in Blocks or a tile merges in 2048, then no animation plays; the state changes immediately.
